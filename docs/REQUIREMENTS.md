# AgentBar 需求文档

> 版本 v0.2 · 2026-11-19 · 状态：待评审
>
> v0.2 变更：菜单栏默认改为多点计数（样式 B）；面板采用液态玻璃；会话显示对应应用的 logo；列表按 主机 → 工作目录 两级分组；新增豆包、DeepSeek 对话；新增一键审批（F10）、面板内查看 Markdown 输出（F11）、一键跳转（F12）

## 1. 背景

在本机和多台 SSH 服务器上同时运行多个 AI 编码 agent（Codex、Claude Code、Cursor、Trae、DeepSeek harness 等）时，很难一眼看出哪个会话在生成、哪个卡在等审批、哪个已经跑完或失败了。AgentBar 是常驻 macOS 菜单栏的只读监控工具，把这些会话汇总到一个面板里。

## 2. 目标与非目标

**目标**

- 一眼看到会话数量，以及有没有需要我处理的会话（待审批 / 失败 / 已完成未查看）
- 统一展示本机和 SSH 服务器上多种 agent 的会话
- 点开会话能看到：当前工具调用、工作目录、Token、供应商与模型、关键指标
- 可选：接入余额 dashboard
- 待审批的会话一键批准 / 拒绝；完成的会话一键跳转，或直接在面板里查看 Markdown 渲染的输出

**非目标（v1）**

- 不在 AgentBar 里给 agent 发消息或终止进程；审批只做“批准一次 / 拒绝”，不做“始终允许”和批量批准
- 不上传任何会话内容，不做云同步
- 不做 iOS / 跨设备同步

## 3. 支持的工具

| 工具 | 本机 | SSH | 主要数据源 | 实时性 | 优先级 |
|---|---|---|---|---|---|
| Claude Code CLI | ✅ | ✅ | `~/.claude/projects/**/*.jsonl` + hooks | 高（hooks） | P0 |
| Codex CLI | ✅ | ✅ | `~/.codex/sessions/YYYY/MM/DD/rollout-*.jsonl` + `notify` | 中 | P0 |
| Codex 桌面版 | ✅ | — | 同 `~/.codex/sessions`，按 `session_meta` 区分来源 | 中 | P0 |
| Claude 桌面版 | ✅ | — | Code 模式预计写入同一批 transcript（待验证）；聊天模式只能做进程级检测 | 低 | P1 |
| DeepSeek Harness | ✅ | ✅ | `DeepSeek Harness.app`（`com.deepseek.dsh`）；日志位置待确认 → 通用 JSONL 适配器或 hook 上报 | 待定 | P1 |
| Cursor | ✅ | — | `~/Library/Application Support/Cursor/User/**/state.vscdb`（SQLite，格式不公开） | 低 | P2 |
| Trae | ✅ | — | 预计与 VS Code 系结构相同（待验证） | 低 | P2 |
| 豆包（桌面版） | ✅ | — | 进程检测 + 窗口标题（需辅助功能权限，可选） | 低 | P1 |
| DeepSeek（对话） | ✅ | — | 同上；本机目前没有单独的对话应用 | 低 | P2 |
| 其他 | ✅ | ✅ | 进程扫描兜底（只知道“在运行”） | 低 | P1 |

本机已确认：`~/.claude/projects` 的 transcript 含 `ai-title`（会话标题）和 assistant `usage`（含 `cache_read_input_tokens` / `cache_creation_input_tokens`）；`~/.codex/sessions` 的 rollout 含 `session_meta`、`turn_context`、`task_started` / `task_complete`、`token_count` 事件。

本机已安装：`ChatGPT.app`（`com.openai.codex`，即 Codex 桌面版，内含 `CodexCLI.app`）、`Claude.app`、`Cursor.app`、`DeepSeek Harness.app`、`Doubao.app`；Trae 未安装。

## 4. 功能需求

### F1 菜单栏图标（P0）

- F1.1 默认样式 B（多点计数）：单色字形 + 各状态的彩色点和数量，例如 `🔴1 🟡1 🟢1 🔵3`
- F1.2 只显示数量不为 0 的状态，顺序固定：🔴 失败 → 🟡 待审批 → 🟢 已完成（未查看）→ 🔵 生成中 / 运行工具；超过 9 显示 `9+`
- F1.3 没有需要关注的会话时只显示单色字形；“等待输入”和“运行中（进程级）”不计入
- F1.4 设置里可切换为样式 A：总数 + 单个最高优先级状态点
- F1.5 适配浅色 / 深色菜单栏；生成中可选轻微呼吸动画（默认关闭）
- F1.6 打开面板后，可见的“已完成 / 失败”会话标记为已查看，对应计数随之减少

### F2 会话列表（P0）

- F2.1 一级分组按 **本机 / 每台 SSH 服务器**，组头显示主机名、连接状态、延迟
- F2.2 二级分组按 **工作目录**，默认合并到所在 git 仓库的根目录；组头显示目录名、缩写路径和状态计数；同一目录下不同工具的会话放在一起
- F2.3 没有工作目录的对话应用（豆包、DeepSeek 对话、Claude 聊天）归到“对话应用”组
- F2.4 一级、二级组头都可以折叠，折叠状态会记住；离线主机默认折叠
- F2.5 每行显示：应用图标 · 会话标题 · 概览小字（单行截断）· 工具 / 模型 / 时长 · 右侧状态胶囊
- F2.6 概览取值优先级：当前工具调用摘要 → 最新 assistant 输出片段 → 用户最后一条 prompt
- F2.7 排序：组内按 需关注（失败 / 待审批）→ 进行中 → 已完成 → 等待输入，再按最近活动时间；目录组按组内最紧急的状态排序
- F2.8 筛选：全部 / 进行中 / 需关注；可按标题或目录搜索；筛选后为空的组自动隐藏
- F2.9 超过 N 小时（默认 12h）没有活动的会话自动隐藏，可在“历史”里查看

### F3 会话详情（P0）

点击一行展开详情：

- 当前工具调用：工具名 + 参数摘要 + 已持续时长（待审批时显示已等待时长）
- 工作目录（可在 Finder / 终端中打开）
- 供应商 + 模型，例如 `Anthropic · claude-opus-5-5`、`OpenAI · gpt-5-codex`
- Token：输入 / 输出 / 缓存读 / 缓存写（以及推理 token，如果有）
- 上下文窗口占用条
- 指标（见 F6）
- 最近 5 次工具调用时间线（名称、耗时、成功 / 失败）
- 操作：跳转到终端 / 应用、打开目录、复制会话 ID、复制恢复命令（如 `claude --resume <id>`、`codex resume <id>`）
- 待审批时显示 批准 / 拒绝（F10）；已完成时显示本轮最终输出（F11）

### F4 SSH 远程（Claude Code / Codex 为 P0）

- F4.1 从 `~/.ssh/config` 读取 Host 列表，用户勾选要监控的主机，也可手动添加
- F4.2 只使用用户现有的 ssh 配置和 ssh-agent，开启 `BatchMode=yes`，不保存密码
- F4.3 远端零部署：只依赖 `sh`、`find`、`stat`、`tail`、`ps`，不要求安装 Swift / Python
- F4.4 刷新频率：面板打开时 5s，关闭时 30s，可配置；主机不可达时显示“离线”并指数退避
- F4.5 支持 ProxyJump / 跳板机（沿用 ssh config）；需要交互式 2FA 的主机，提示用户先手动建立 ControlMaster 连接

### F5 余额 Dashboard（P1，可选）

- F5.1 可添加多个余额源，每个包含名称、类型、刷新间隔、低余额阈值
- F5.2 三种类型：
  - **JSON API**：URL + 请求头（token 存钥匙串）+ JSONPath 提取，例如 DeepSeek `GET /user/balance`
  - **网页提取**：在 AgentBar 内置浏览器里登录一次（适合需要 SSO 的内部 dashboard），用 CSS 选择器或 JS 表达式提取数值
  - **自定义命令**：执行用户提供的 shell 命令，取 stdout 中的第一个数字（可复用已有的 curl、证书或 CLI）
- F5.3 面板顶部显示余额卡片：数值、本期已用比例（拿得到时）、更新时间；低于阈值时标红并发通知

### F6 Agent 指标（P1）

| 指标 | 含义 | 计算方式 |
|---|---|---|
| 上下文占用率 | 当前会话用掉了多少模型上下文窗口（agent 的“记忆”还剩多少） | 最近一次请求的输入 token / 模型窗口 |
| 缓存命中率 | prompt 中命中缓存的比例，越高越省钱、越快 | Claude：`cache_read / (input + cache_read + cache_creation)`；Codex：`cached_input / input` |
| 进程内存 | agent 进程的物理内存占用 | 本机 `phys_footprint`；远端 `ps rss` |
| CPU | agent 进程 CPU 占用 | 定时采样 |
| 输出速度 | 每秒输出 token 数 | 输出 token / 生成耗时 |
| 工具调用成功率 | 工具调用中没有报错的比例 | 成功次数 / 总次数 |
| 审批等待时长 | 卡在待审批的累计 / 平均时长 | hook 时间戳 |
| 每轮耗时 | 从用户提交到本轮结束 | `task_started` → `task_complete` |
| 上下文压缩次数 | 触发 compact 的次数 | compact 事件计数 |
| 错误 / 重试次数 | API 错误、限流 | 错误事件计数 |
| 预估成本 | 按价目表估算 | 用户可编辑的价目表 × token |

面板底部显示今日汇总：总 token、平均缓存命中率、预估成本。

### F7 通知（P1）

- 会话进入 待审批 / 已完成 / 失败 时发系统通知，可按状态、按工具单独开关
- 点击通知 → 打开面板并定位到对应会话
- 待审批通知带“批准 / 拒绝”按钮（仅限支持回传的工具，见 F10）
- 遵循系统专注模式

### F8 设置（P0）

- 启用的工具与路径覆盖、SSH 主机、刷新间隔、图标样式、通知、余额源、价目表、开机自启（`SMAppService`）
- “安装 hooks”向导：先预览要写入 `~/.claude/settings.json` / `~/.codex/config.toml` 的 diff，确认后才写入，并自动备份原文件

### F9 视觉风格与应用图标（P0）

- F9.1 面板采用 macOS 26 的液态玻璃（Liquid Glass），与系统菜单、控制中心保持一致：玻璃面板、玻璃胶囊、玻璃按钮和分段控件，圆角同心
- F9.2 遵循系统的“降低透明度”“增强对比度”设置，自动换成不透明材质
- F9.3 每个会话显示对应应用的 logo，运行时从已安装的应用读取，安装包里不打包品牌 logo
- F9.4 同一家的不同形态要能区分：命令行版在 logo 右下角加 `>_` 角标（Claude Code CLI、Codex CLI），对话应用加蓝色气泡角标（豆包、DeepSeek 对话）；桌面 agent 应用（Claude、Codex、Cursor、Trae、DeepSeek Harness）不加角标
- F9.5 对应应用没有安装时（例如 Trae）使用内置的单色占位图标

### F10 一键审批（P1）

- F10.1 待审批的会话在列表行上直接显示“批准 / 拒绝 / 在终端处理”，不需要展开；系统通知上也有“批准 / 拒绝”按钮
- F10.2 支持范围：Claude Code CLI（本机 + SSH）通过 hook 回传决定；Codex 和其他工具暂时没有回传通道，按钮换成“跳转到终端”
- F10.3 只提供“批准一次”和“拒绝”（可以附一句原因给 agent）；不做“始终允许”，也不做批量批准
- F10.4 高风险命令（`rm -rf`、`sudo`、`git push --force`、`curl … | sh`、写入工作目录之外的路径等，规则可配置）需要二次确认
- F10.5 用户点“在终端处理”，或 AgentBar 在超时时间（默认 120s）内没有给出决定，就交回终端里的原生审批，不会卡死 agent
- F10.6 每次决定写入本地审计日志：时间、主机、会话、工具调用、决定
- F10.7 可以按主机或全局关闭“由 AgentBar 审批”，关闭后只通知、不拦截

### F11 查看输出（P1）

- F11.1 已完成（以及等待输入）的会话展开后显示本轮最终输出，按 Markdown 渲染：标题、列表、代码块（等宽 + 复制按钮）、表格、链接
- F11.2 内容超过卡片高度时在卡片内滚动；可以“在窗口中打开”成独立窗口，或“复制 Markdown”
- F11.3 输出只在展开时从日志里按需读取，不缓存到磁盘；远端会话通过 SSH 读取
- F11.4 不加载远程图片，只显示链接

### F12 一键跳转（P0）

- F12.1 每个会话都能一键跳转；已完成的会话在列表行上直接显示跳转按钮（↗）
- F12.2 本机 CLI：找到进程所在的终端标签页并切到前台（Terminal、iTerm2）；其他终端只激活应用
- F12.3 桌面应用（Codex、Claude、Cursor、Trae、DeepSeek Harness、豆包）：激活对应应用
- F12.4 远端会话：在 tmux 里就打开终端并 attach 到对应 pane；否则打开 `ssh <host>` 进入工作目录，并复制恢复命令

## 5. 状态定义

| 状态 | 颜色 | 含义 | 判定依据（详见设计文档 §7） |
|---|---|---|---|
| 生成中 | 蓝 | 模型正在输出 | 本轮已开始、未结束，最近事件是模型输出 |
| 运行工具 | 蓝（带工具名） | 正在执行工具 | 存在未结束的工具调用 |
| 待审批 | 黄 | 等待用户批准工具调用 | hook 权限通知；没有 hook 时用启发式并标注“推测” |
| 等待输入 | 灰 | 本轮已结束、进程还在，等用户发下一条 | 本轮结束 + 进程存活 + 已查看 |
| 运行中（进程级） | 灰（空心点） | 只知道应用在运行，拿不到会话细节（对话应用，或 Cursor / Trae 解析失败降级） | 进程存活 |
| 已完成 | 绿 | 刚完成且未查看 | 本轮结束且用户还没看过 |
| 失败 | 红 | API 错误 / 进程异常退出 / 工具连续失败 | 错误事件 / 非零退出码 |
| 空闲 | 浅灰 | 进程已退出或长时间无活动 | 超时 |
| 离线 | 灰色虚线 | 远程主机不可达 | SSH 失败，保留最后已知状态 |

## 6. 非功能需求

- 性能：空闲 CPU < 0.5%，内存 < 100 MB，面板打开 < 100 ms
- 时效：本机装了 hooks 时状态延迟 < 1s，没装 < 2s；远端约等于刷新间隔
- 隐私：只读访问日志；会话内容不离开本机；密钥只存在钥匙串
- 兼容：macOS 26+（液态玻璃 API 需要），Apple Silicon 与 Intel
- 健壮：某个工具的日志格式变化只影响对应适配器，不崩溃，界面显示“解析失败”

## 7. 待确认问题

1. 内部 dashboard 怎么访问：浏览器 SSO 登录？有没有 JSON 接口？需要 VPN 吗？这决定用 F5 的哪种类型
2. DeepSeek Harness 的会话日志在哪里？本机装了 `DeepSeek Harness.app`（`com.deepseek.dsh`），但 `~/Documents/deepseek-harness/default-workspace` 里只有工作区文件
3. 要监控哪些 SSH 主机？有没有跳板机或交互式 2FA？
4. 最低版本定为 macOS 26 可以吗？（液态玻璃需要；开发机是 macOS 27）
5. 是否允许 AgentBar 写入 `~/.claude/settings.json` 和 `~/.codex/config.toml` 安装 hooks（先预览、自动备份）？
6. 一键审批的默认超时（120s）和高风险规则清单合适吗？注意：等待 AgentBar 决定的这段时间里，终端里不会出现原生审批提示
7. 项目名 AgentBar 可以吗？
8. 豆包 / DeepSeek 对话要不要显示窗口标题？需要授予辅助功能权限
9. 跳转到 Terminal / iTerm2 的具体标签页需要“自动化”权限，可以接受吗？你平时用哪个终端？
